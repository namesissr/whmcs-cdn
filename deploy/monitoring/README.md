# Monitoring stack (Prometheus + Alertmanager + Grafana)

Full guide (Persian): [docs/MONITORING.md](../../docs/MONITORING.md).

```sh
cd deploy/monitoring
cp .env.example .env && chmod 600 .env && $EDITOR .env
docker compose up -d                          # core: /metrics + blackbox probes
docker compose --profile api-bridge up -d     # optional per-edge / traffic / security panels
```

| Path | What |
|---|---|
| `docker-compose.yml` | Prometheus, Alertmanager, Grafana (127.0.0.1 only), blackbox, optional json-exporter |
| `render-config.sh` | renders file_sd targets + `alertmanager.yml` from the environment at container start |
| `prometheus/prometheus.yml` | scrape jobs (`pcdn-controller` with Bearer `METRICS_TOKEN`, probes, bridge) |
| `prometheus/rules/pcdn-alerts.yml` | alert rules; unit tests in `prometheus/tests/` |
| `alertmanager/templates/pcdn.tmpl` | Persian Telegram / e-mail messages |
| `json-exporter/config.yml` | admin-API → `pcdn_api_*` mapping (api-bridge profile) |
| `grafana/dashboards/*.json` | generated by `tools/gen_dashboards.py` — do not edit by hand |
| `tools/check_monitoring.py` | CI checks (dashboards, metric names exist, PromQL parses with promtool) |
| `same-host.override.yml` | scrape over the control plane's Docker network instead of HTTPS |

Validate locally:

```sh
python3 deploy/monitoring/tools/check_monitoring.py      # uses promtool from PATH or $PROMTOOL
cd deploy/monitoring && promtool check rules prometheus/rules/*.yml \
  && (cd prometheus && promtool test rules tests/pcdn-alerts.test.yml)
```
