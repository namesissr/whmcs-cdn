# صفحهٔ وضعیت عمومی پاسارگاد سی‌دی‌ان

یک صفحهٔ **ایستا و کاملاً مستقل** (بدون CDN، فونت یا وابستگی بیرونی) که هر ۳۰ ثانیه
فایل عمومی `/status.json` کنترلر را می‌گیرد و وضعیت سرویس‌ها، اجزا، نودها و رخدادها را
به‌صورت فارسی (RTL، حالت روشن/تیره) نمایش می‌دهد. مطابق «SPEC §۸.۲».

## فایل‌ها
- `index.html` — صفحهٔ اصلی
- `status.css` — استایل (روشن/تیره، واکنش‌گرا)
- `status.js` — گرفتن و نمایش `/status.json`
- `abuse.html` + `abuse.js` — فرم عمومی **گزارش تخلف** و پیگیری وضعیت (پایین را ببینید)
- `tests/abuse.test.js` — آزمون حل‌کنندهٔ proof-of-work زیر node (`node --test status/tests/*.test.js`)

## میزبانی
کل پوشهٔ `status/` را روی هر میزبان ایستا آپلود کنید. چند گزینه:

- **همان دامنهٔ WHMCS** — مثلاً در `public_html/status/`. آدرس: `https://example.com/status/`.
- **یک زیردامنه** — مثل `status.example.com` که به همین پوشه اشاره کند.
- **آبجکت‌استوریج / GitHub Pages / Netlify** و مانند آن‌ها.

هیچ سرور اجرایی لازم نیست؛ فقط سرو فایل ایستا کافی است.

## اتصال به کنترلر
مبدأ `status.json` به این ترتیب تعیین می‌شود:

1. **پارامتر `?api=`** در نشانی صفحه (بالاترین اولویت):
   ```
   https://status.example.com/?api=https://cdn-api.example.com
   ```
2. **ثابت `API_BASE`** در ابتدای `status.js`:
   ```js
   const API_BASE = "https://cdn-api.example.com";
   ```
3. اگر هیچ‌کدام تنظیم نشد، صفحه فایل `/status.json` را از **همان مبدأیی** که صفحه از آن
   سرو می‌شود می‌گیرد (وقتی صفحه و کنترلر روی یک دامنه‌اند، نیازی به تنظیم نیست).

اگر صفحه روی دامنه‌ای جدا از کنترلر میزبانی شود، مرورگر برای خواندن `/status.json`
به CORS نیاز دارد؛ کنترلر برای این مسیر عمومی هدر لازم را می‌دهد. در غیر این‌صورت از `?api=`
استفاده کنید.

## نکات
- این صفحه فقط دادهٔ **عمومی و تجمیعی** را نشان می‌دهد: هیچ IP، نام نود، منطقه یا دامنهٔ
  مشتری افشا نمی‌شود؛ تنها شمارش کل/آنلاین نودها و متن رخدادهایی که اپراتور نوشته است.
- اگر `/status.json` در دسترس نباشد، پیام «در حال حاضر نمی‌توان وضعیت را دریافت کرد»
  نمایش داده می‌شود و تلاش خودکار ادامه می‌یابد.

## فرم گزارش تخلف (`abuse.html`)
صفحهٔ عمومی گزارش تخلف (SPEC §23.10)، مستقل و بدون وابستگی مثل صفحهٔ وضعیت، فارسی RTL با دکمهٔ «English»
(انتخاب زبان در مرورگر نگه داشته می‌شود؛ `?lang=en` هم کار می‌کند). از پایین صفحهٔ وضعیت پیوند دارد.

- **کنترلر:** باید `ABUSE_ENABLED=true` باشد؛ در غیر این‌صورت فرم پیام «ثبت گزارش تخلف در حال حاضر فعال نیست»
  نشان می‌دهد. مبدأ API مثل صفحهٔ وضعیت است: `?api=` ← ثابت `ABUSE_API_BASE` در `abuse.js` ← همان مبدأ صفحه.
  مسیرهای `/public/v1/abuse/*` برای GET/POST هدر CORS `*` دارند.
- **ارسال:** دسته (فیشینگ، بدافزار، غیرقانونی، هرزنامه، حق نشر، سایر)، ۱ تا ۱۰ نشانی http(s)، توضیح (حداکثر
  ۴۰۰۰ نویسه)، ایمیل اختیاری. پیش از ارسال یک چالش از `GET /public/v1/abuse/challenge` گرفته و **proof of work**
  حل می‌شود: نخستین `nonce` دهدهی که `sha256(salt + nonce)` (UTF-8، `salt` همان رشتهٔ hex دریافتی) دست‌کم
  `bits` بیت صفر در ابتدا داشته باشد (در مرورگر حدود یک ثانیه برای ۲۰ بیت؛ کار در برش‌های کوچک انجام می‌شود تا
  صفحه قفل نشود). فیلد پنهان `website` تله (honeypot) است و باید خالی بماند.
- **نتیجه:** شمارهٔ پیگیری `AB-…` و کد پیگیری که **فقط یک بار** نمایش داده می‌شود؛ با این دو در بخش «پیگیری
  وضعیت گزارش» فقط وضعیت، زمان‌ها و یادداشت عمومی دیده می‌شود (`GET /public/v1/abuse/reports/{ticket}?token=…`).
- **حریم خصوصی:** صفحه هیچ کوکی یا ذخیرهٔ داده‌ای جز انتخاب زبان ندارد؛ درخواست‌ها با `credentials: "omit"`
  فرستاده می‌شوند و صفحه `referrer` نمی‌فرستد.
