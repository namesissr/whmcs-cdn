# راهنمای عملیات نودها (Nodes) — CDN پاسارگاد

این سند برای مدیر فنی است و به راه‌اندازی سریع، پایش و نگه‌داری نودهای لبه (Edge) می‌پردازد:
نصب تک‌دستوری، افزودن گروهی، تعیین منطقه و نقش، خواندن لاگ‌های متمرکز، به‌روزرسانی و از رده خارج
کردن نود، و جدول عیب‌یابی. این سند مکمل [OPERATIONS.md](OPERATIONS.md) (سرور مرکزی) و
[EDGE.md](EDGE.md) (جزئیات فنی نود) است. پیاده‌سازی مطابق `docs/SPEC.md` §11 است.

## پیش‌نیازها

- یک سرور تازه **Ubuntu 24.04 LTS** با دسترسی root (یا sudo) و IP عمومی.
- دامنه عمومی سرور مرکزی (کنترلر) که با متغیر `CONTROLLER_DOMAIN` در `.env` تنظیم شده است
  (مثلاً `cdn-api.pasargadmizban.com`). نودها بسته و پیکربندی را از همین آدرس می‌گیرند.
- یک «توکن یک‌بارمصرف» برای هر نود که هنگام ساخت نود در پنل WHMCS (یا API مدیریتی) صادر می‌شود و
  فقط همان یک‌بار نمایش داده می‌شود.
- پورت‌های 80 و 443 باز باشند؛ اگر IPv6 دارید، هر دو خانواده آدرس به کنترلر برسند.

> بسته‌ی نود (`/edge/bundle.tar.gz`) فقط شامل عامل (agent) و قالب‌های متن‌باز است و **هیچ رمز،
> کلید یا توکنی ندارد**؛ بنابراین مسیرهای `GET /edge/bootstrap.sh`، `GET /edge/bundle.tar.gz` و
> `GET /edge/version` روی کنترلر بدون احراز هویت سرو می‌شوند.

## ۱. نصب تک‌دستوری

پس از ساخت نود در پنل و گرفتن توکن، روی سرور نود این تک‌دستور را اجرا کنید:

```bash
curl -fsSL https://<controller>/edge/bootstrap.sh | sudo bash -s -- \
    --controller https://<controller> --token edge_xxxxxxxx
```

`bootstrap.sh` بسته را از کنترلر دانلود می‌کند، باز می‌کند و `install.sh` را با همان پرچم‌ها اجرا
می‌کند. پرچم‌های قابل انتقال:

| پرچم | توضیح |
|---|---|
| `--region home\|global` | منطقه/استخر DNS نود (پیش‌فرض `global`) |
| `--role general\|tunnel` | نقش نود که به «گروه» نود نگاشت می‌شود (پیش‌فرض `general`) |
| `--cache-size 50g` | حداکثر فضای کش هر سایت (پیش‌فرض `10g`) |
| `--http-port N` / `--https-port N` | پورت‌های عمومی (پیش‌فرض 80/443) |
| `--no-ipv6` | گوش‌ندادن روی IPv6 |
| `--no-geoip` | دانلود نشدن پایگاه کشور DB-IP |
| `--upgrade` | به‌روزرسانی نود نصب‌شده در جا (بخش ۶) |

رشته‌ی آماده‌ی هر نود (شامل توکن) در پنل WHMCS، صفحه‌ی «نودها» نمایش داده می‌شود؛ یا از API:

```bash
curl -s -H "Authorization: Bearer $ADMIN_API_KEY" \
  "https://<controller>/api/v1/edges/install?token=edge_xxx&region=home&role=tunnel"
# => {"command": "curl -fsSL https://<controller>/edge/bootstrap.sh | sudo bash -s -- ..."}
```

بررسی سلامت پس از نصب:

```bash
systemctl status pcdn-agent
journalctl -u pcdn-agent -f
curl -H 'Host: health.pcdn' http://127.0.0.1/__pcdn/health
```

> اگر کنترلر بسته را سرو نکند (متغیر `EDGE_BUNDLE_DIR` تنظیم/موجود نباشد)، هر دو مسیر بسته 404 با
> پیام روشن برمی‌گردانند و پنل به روش دستی (git/scp) ارجاع می‌دهد. مسیر نصب دستی در EDGE.md آمده است.

## ۲. افزودن گروهی نودها

برای بالا آوردن چند نود هم‌زمان، از API مدیریتی استفاده کنید:

```bash
curl -s -X POST -H "Authorization: Bearer $ADMIN_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"count": 5, "region": "home", "group": "tunnel", "name_prefix": "ir", "capacity_mbps": 1000}' \
  "https://<controller>/api/v1/edges/batch"
```

پاسخ، آرایه‌ای از نودهای ساخته‌شده است؛ هر عضو شامل مشخصات نود، `token` یک‌بارمصرف و `install`
(همان تک‌دستور آماده) است. نام‌ها به‌صورت `name_prefix-<شماره>` و بدون تداخل با نام‌های موجود ساخته
می‌شوند (`count` بین 1 تا 50). در پنل WHMCS همین کار با فرم «افزودن گروهی» انجام می‌شود و فهرست
دستورهای آماده برای کپی نمایش داده می‌شود.

IP نود در زمان ساخت گروهی نامشخص است؛ نود در نخستین heartbeat خود را معرفی می‌کند و تا آنلاین‌شدن
وارد پاسخ‌های DNS نمی‌شود.

## ۳. منطقه و نقش (region / role)

- **region**: `home` (نودهای داخل کشور) یا `global`. تعیین می‌کند نود در کدام استخر GeoDNS پاسخ دهد.
- **role**: `general` یا `tunnel`؛ به «گروه» نود نگاشت می‌شود و مشخص می‌کند نود به سایت‌های پلن عادی
  خدمت دهد یا به سایت‌های حالت تونل (VPN-over-CDN، SPEC §7.4).

منطقه و نقش هنگام **ساخت نود** روی کنترلر تعیین می‌شوند (پنل یا `POST /api/v1/edges[/batch]`) و در
تک‌دستور نصب همان نود گنجانده می‌شوند. `install.sh` این مقادیر را در `/etc/pcdn/agent.conf`
(`REGION=` و `GROUP=`) ذخیره می‌کند و عامل آن‌ها را **فقط در نخستین heartbeat** گزارش می‌دهد تا یک
نود تازه خودکار در استخر درست ثبت شود. تغییرهای بعدی اپراتور از طریق پنل، دیگر با heartbeatها بازنویسی
نمی‌شوند. برای جابه‌جایی یک نود موجود بین استخرها از پنل (یا `PATCH /api/v1/edges/{id}`) استفاده کنید.

## ۴. نصب خودکار با cloud-init

برای بالا آمدن خودکار در نخستین بوت، محتوای `edge/cloud-init.yaml.example` را در بخش «user data»
ماشین قرار دهید و دو مقدار `CONTROLLER` و `TOKEN` (و در صورت نیاز region/role) را جایگزین کنید. این
قالب همان تک‌دستور نصب را اجرا می‌کند.

## ۵. خواندن لاگ‌های نود

هر نود فقط خطوط مشکل‌دار عملیاتی (`warn`/`error`/`crit`) از لاگ خطای nginx و لاگ خود عامل را، روی
کادنس heartbeat، به `POST /edge/v1/logs` می‌فرستد. لاگ دسترسی (access)، بدنه‌ی درخواست‌ها، IP بازدید‌کننده‌ها،
توکن‌ها و کلیدها **هرگز** ارسال نمی‌شوند (IPها و توکن‌ها روی نود سانیتایز می‌شوند). حجم هم محدود است:
حداکثر ~۴۰ خط در هر گزارش و ~۵۰۰ کاراکتر در هر خط، و روی کنترلر یک حلقه‌ی سقف‌دار (~۱۲۰ خط / ~۱۶ کیلوبایت،
قدیمی‌ترها حذف می‌شوند) نگه‌داری می‌شود؛ پس یک نود پرسروصدا نمی‌تواند کنترلر را پر کند.

مشاهده‌ی لاگ‌های یک نود:

```bash
curl -s -H "Authorization: Bearer $ADMIN_API_KEY" \
  "https://<controller>/api/v1/edges/<id>/logs"
# => {"name": "...", "logs_at": "...Z", "lines": [{"t","level","msg"}, ...]}
```

خطوط به‌صورت «قدیمی→جدید» (newest last) ذخیره می‌شوند؛ رابط کاربری آن‌ها را برعکس (جدیدترین بالا) و
با رنگ‌بندی سطح نمایش می‌دهد. در پنل WHMCS، صفحه‌ی «نودها» دکمه‌ی «لاگ‌ها» برای هر نود دارد. فهرست
`GET /api/v1/edges` هم دو نشانگر سبک `logs_at` و `has_logs` دارد (بدون خود خطوط).

## ۶. به‌روزرسانی یک نود

به‌روزرسانی یعنی اجرای دوباره‌ی همان تک‌دستور با پرچم `--upgrade`؛ هیچ کد از راه دور push نمی‌شود.
کنترلر، بسته را به‌روز سرو می‌کند و `--upgrade` تنظیمات موجود (controller، token، پورت‌ها، IPv6، اندازه
کش، region و role) را از `/etc/pcdn/agent.conf` می‌خواند:

```bash
curl -fsSL https://<controller>/edge/bootstrap.sh | sudo bash -s -- \
    --controller https://<controller> --token edge_xxxxxxxx --upgrade
```

نسخه‌ی بسته‌ی درحال‌اجرا را عامل در heartbeat گزارش می‌دهد (`bundle_version`) و کنترلر آن را با نسخه‌ی
جاری بسته مقایسه می‌کند:

```bash
curl -s https://<controller>/edge/version       # => {"version": "<hash>"}
```

اگر نسخه‌ی نود عقب باشد، پنل نشان «به‌روزرسانی موجود است» را برای آن نود نمایش می‌دهد.

## ۷. از رده خارج کردن نود (Decommission)

1. ابتدا نود را در پنل **غیرفعال** کنید (یا `PATCH /api/v1/edges/{id}` با `{"enabled": false}`)؛
   این کار آن را از پاسخ‌های DNS خارج می‌کند تا ترافیک تازه نگیرد.
2. چند دقیقه صبر کنید تا اتصال‌های باز تخلیه شوند و TTL رکوردها منقضی شود.
3. روی نود سرویس‌ها را متوقف کنید: `systemctl disable --now pcdn-agent nginx`.
4. در پایان نود را **حذف** کنید (`DELETE /api/v1/edges/{id}` یا دکمه‌ی حذف در پنل)؛ توکن نیز باطل
   می‌شود. سرور را می‌توانید نابود کنید.

## ۸. جدول عیب‌یابی

| نشانه | علت محتمل | بررسی / راه‌حل |
|---|---|---|
| نود آفلاین (بدون heartbeat) | عامل متوقف است یا کنترلر/شبکه در دسترس نیست | `systemctl status pcdn-agent`؛ `journalctl -u pcdn-agent -f`؛ دسترسی به `https://<controller>/edge/version`؛ درستی `CONTROLLER_URL` و `EDGE_TOKEN` در `/etc/pcdn/agent.conf` |
| probe خطا می‌دهد ولی heartbeat سالم است («گزارش می‌دهد اما خراب») | nginx بالا نیست یا `/__pcdn/health` پاسخ نمی‌دهد | `nginx -t`؛ `systemctl status nginx`؛ `curl -H 'Host: health.pcdn' http://127.0.0.1/__pcdn/health`؛ باز بودن پورت 80 از سمت کنترلر |
| خطای پیکربندی (config error) پس از سینک | قالب یا گواهی نامعتبر، `nginx -t` شکست خورده | لاگ‌های نود (`/api/v1/edges/{id}/logs`) و `journalctl -u pcdn-agent`؛ عامل پیکربندی بد را rollback می‌کند و خطا را در heartbeat گزارش می‌دهد |
| نود اشباع/شِد (`shed`) | مصرف پهنای‌باند از `capacity_mbps` عبور کرده | ظرفیت نود را در پنل تنظیم کنید یا نود بیشتری اضافه کنید؛ نود پس از افت بار خودکار برمی‌گردد (SPEC §7.4) |
| مشکل گواهی (cert) | صدور/تمدید ACME ناموفق یا گواهی منقضی | بخش گواهی‌ها در OPERATIONS.md؛ هشدار `alert_cert_days`؛ لاگ‌های نود برای خطای SSL |
| «به‌روزرسانی موجود است» | نسخه‌ی بسته‌ی نود عقب است | اجرای تک‌دستور با `--upgrade` (بخش ۶) |
| نصب: دانلود بسته ناموفق | کنترلر در دسترس نیست یا `EDGE_BUNDLE_DIR` تنظیم نیست | دسترسی به `https://<controller>/edge/bundle.tar.gz`؛ تنظیم `EDGE_BUNDLE_DIR` روی کنترلر یا نصب دستی (EDGE.md) |

برای پایش کلی نودها، صفحه‌ی وضعیت عمومی و رخدادها، بخش ۸ [OPERATIONS.md](OPERATIONS.md#۸-پایش-سلامت-نودها-صفحه-وضعیت-عمومی-و-رخدادها-spec-8) را ببینید.
