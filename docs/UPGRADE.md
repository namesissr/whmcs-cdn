# راهنمای اعمال به‌روزرسانی‌ها — CDN پاسارگاد

این سند، گام‌به‌گام می‌گوید چطور **همه‌ی** به‌روزرسانی‌های این شاخه را روی یک سیستمِ در حال کار اعمال
کنید: سرور کنترلر، نودهای لبه، و WHMCS. اگر هنوز هیچ‌کدام را اعمال نکرده‌اید، همین ترتیب را از بالا به
پایین دنبال کنید.

> ترتیب مهم است: **پشتیبان → کنترلر → نودها → WHMCS**. کنترلر را قبل از نودها به‌روزرسانی کنید، چون
> بسته‌ی نصبِ نودها را خودِ کنترلر سرو می‌کند.

جزئیات بیشترِ هر بخش: `docs/OPERATIONS.md` (عملیات کنترلر)، `docs/NODES.md` (نودها)،
`docs/WHMCS.md` (ماژول WHMCS)، `docs/ARCHITECTURE.md` (معماری)، `docs/DISASTER_RECOVERY.md`
(بازیابی از فاجعه)، `docs/SECURITY.md` (سخت‌سازی امنیتی) و `docs/TERRAFORM.md` (Terraform برای مشتریان).

> مسیرهای مثال‌ها: روی سرور کنترلر و روی نودها کد در `/opt/pcdn` است و دامنه‌ی کنترلر
> `cdn-api.pasargadmizban.com`؛ اگر جای دیگری نصب کرده‌اید، مسیر خودتان را بگذارید.

## ۰) پیش از شروع — پشتیبان بگیرید

روی سرور کنترلر:

```bash
cd /path/to/whmcs-cdn
docker compose exec controller python -m app.manage backup   # پشتیبان دیتابیس کنترلر + PowerDNS + acme
```

- از دیتابیس WHMCS هم طبق روال خودتان یک پشتیبان بگیرید (این به‌روزرسانی جدول‌های `mod_pasargadcdn_*`
  را می‌سازد/تغییر می‌دهد).
- کلید رمزنگاری (`DATA_ENCRYPTION_KEY`) و رمز پشتیبان را جایی بیرون از سرور داشته باشید.

کد جدید را بیاورید:

```bash
git fetch origin
git checkout claude/cdn-whmcs-setup-5vxr95
git pull
```

## ۱) سرور کنترلر

```bash
cd /path/to/whmcs-cdn
docker compose build controller
docker compose up -d
```

نکات این نسخه:

- **مهاجرت دیتابیس.** کنترلر هنگام بالا آمدن، مهاجرت‌ها را تا نسخه‌ی `0019` زیر یک قفل اجرا می‌کند
  (موج ۹: `0019` مالک دامنه‌ها و شناسه‌های یکتای سایت/پاک‌سازی؛ موج ۸: `0017` پروکسی TCP/UDP و رکوردهای وزن‌دار، `0018` فضای ذخیره‌سازی؛ موج ۷: `0016` رویدادهای قطعی تونل؛ موج ۶: `0013` قابلیت‌ها و Shield نودها، `0014` گواهی mTLS مبدأ، `0015` آمار دقیقه‌ای، صف لاگ و
  وب‌هوک‌ها). حتماً بررسی کنید:
  ```bash
  docker compose exec controller python -m app.manage current   # باید «current» و «head» هر دو 0019 باشند
  ```
  اگر `current` از `head` عقب‌تر بود (مثلاً `0018 head 0019`) یا `‎/healthz` خطای 502 داد، مهاجرت را دستی
  اجرا و کنترلر را ری‌استارت کنید:
  ```bash
  docker compose exec controller python -m app.manage migrate
  docker compose restart controller
  ```
- **تغییر `docker-compose.yml`:** حالا پوشه‌ی `./edge` به‌صورت فقط‌خواندنی داخل کنترلر مونت می‌شود و
  `EDGE_BUNDLE_DIR=/srv/edge` ست شده است. این همان بسته‌ی بدونِ‌رمزی است که برای «نصب تک‌دستوری نود»
  از `‎/edge/bootstrap.sh` و `‎/edge/bundle.tar.gz` سرو می‌شود. چون compose عوض شده، حتماً
  `docker compose up -d` را اجرا کنید تا کانتینر با مونت جدید دوباره ساخته شود.
- **متغیرهای جدید `.env` (اختیاری، همه پیش‌فرضِ امن دارند):** برای تنظیم دقیق‌تر می‌توانید این‌ها را در
  `.env` بگذارید؛ اگر نگذارید، مقدار پیش‌فرض به کار می‌رود:
  - `CAPI_RATE` (پیش‌فرض ۶۰)، `CAPI_CONFIG_RATE` (۶) — سقف نرخ API مشتری.
  - پایداری/DNS نودها: `EDGE_SHED_CHECKS` (۳)، `EDGE_SHED_HOLD` (۳۰۰)، `EDGE_CPU_SHED` (۰=خاموش)،
    `EDGE_SILENT_GUARD_FRACTION` (۰٫۵)، `PROBE_WITHDRAW_MAX_FRACTION` (۰٫۳۴)،
    `TUNNEL_LUA_SELECTOR` (`all`). توضیح هرکدام در `docs/NODES.md` §۱۰.
  - مشاهده‌پذیری/حسابرسی (موج ۵): `METRICS_TOKEN` (خالی = `‎/metrics` باز است؛ اگر مقدار بگذارید،
    اسکرپ باید `Authorization: Bearer` بفرستد)، `AUDIT_RETENTION_DAYS` (۹۰ = چند روز لاگ حسابرسی نگه‌داری شود).
  - مدیریت ربات‌ها (موج ۶): `BOT_RANGES_ENABLED` (`true`؛ کنترلر روزی یک‌بار فهرست IP خزنده‌های گوگل و
    بینگ را از اینترنت — از طریق `HTTPS_PROXY` اگر ست باشد — می‌گیرد؛ روی کنترلرِ بدون اینترنت `false`
    بگذارید)، `BOT_RANGES_STALE_DAYS` (۳).
  - تحلیل و پلتفرم (موج ۶): `LOG_EXPORT_MAX_PER_HOUR` (۵۰۰۰۰۰ رکورد لاگ در ساعت برای هر سایت)،
    `ATTACK_EVENTS_PER_5M` (۱۰۰۰ — آستانه‌ی وب‌هوک «حمله»).
- موج ۷ (کیفیت تونل): `TUNNEL_ORIGIN_CHECK` (`true` — تشخیص قطعی سرور پشت تونل)،
    `SITE_EVENTS_RETENTION_DAYS` (۳۰)، `CAPACITY_ALERT_PERCENT` (۷۰) و `CAPACITY_RESOLVE_PERCENT` (۶۰) برای
    هشدار ظرفیت گروه نودها، `FAIR_SHARE_PCT` (۲۵). **برای کارکرد هشدار ظرفیت و تقسیم منصفانه، ظرفیت
    (Mbps) هر نود را در پنل مدیریت → نودها وارد کنید.**
- **اتصال خروجی کنترلر (موج ۶):** وب‌هوک‌های مشتری و آپلود لاگ به S3 مشتری **مستقیم** (نه از طریق
  `HTTPS_PROXY`) و فقط به آدرس‌های عمومی و https وصل می‌شوند. اگر سرور کنترلر اینترنت مستقیم ندارد، این
  دو قابلیت روی آن کار نمی‌کنند (بقیه‌ی سامانه بی‌اثر است).
- **امنیت:** صفحه‌های `‎/docs`، `‎/redoc` و `‎/openapi.json` کنترلر دیگر عمومی نیستند (فهرست مسیرهای
  مدیریتی را لو می‌دادند). مستندات API مشتری در `‎/capi/v1/openapi.json` است. گواهی عمومی CA برای
  احراز هویت مبدأ هم در `‎/origin-pull-ca.pem` سرو می‌شود (فقط گواهی؛ کلید هرگز بیرون نمی‌رود).
- بررسی سلامت و مشاهده‌پذیری:
  ```bash
  curl -fsS https://<دامنه-کنترلر>/healthz
  curl -fsS https://<دامنه-کنترلر>/metrics | head        # متریک‌های Prometheus (فقط آمار تجمیعی، بدون دامنه/IP)
  docker compose exec controller python -m app.manage alerts-test     # (اختیاری) آزمایش هشدارها
  docker compose exec controller python -m app.manage backup-verify   # (اختیاری) آزمونِ قابل‌بازیابی‌بودن آخرین پشتیبان
  ```
  > `‎/metrics` را فقط روی شبکه‌ی داخلیِ پایش در دسترس بگذارید، یا با `METRICS_TOKEN` محافظتش کنید.

## ۲) نودهای لبه (هر نود)

هر نود را با همان **دستور تک‌خطی** در حالت ارتقا به‌روزرسانی کنید. کنترلر، آدرس و توکن و تنظیمات قبلی
را از `/etc/pcdn/agent.conf` می‌خواند، پس فقط `--upgrade` کافی است:

```bash
curl -fsSL https://<دامنه-کنترلر>/edge/bootstrap.sh | sudo bash -s -- --upgrade
```

این کار بسته‌ی جدید را از کنترلر می‌گیرد، `install.sh` را دوباره اجرا می‌کند و ایجنت و nginx را
به‌روز می‌کند. تغییرات این نسخه روی نود (همه با پیش‌فرضِ امن):

- تیونینگ nginx و کرنل برای پایداری تونل: `worker_shutdown_timeout`، `multi_accept off` + `reuseport`،
  بافرها و تایم‌اوت‌های تونل، `so_keepalive`، conntrack، و فایل sysctl با نام جدید `999-pcdn.conf`
  (نسخه‌ی قدیمی خودکار پاک می‌شود).
- هماهنگی ریلودِ nginx (coalesce/diff-skip/verify) و ارسالِ idempotentِ مصرف.
- کلیدهای جدیدِ `agent.conf` (مثل `TUNNEL_H2_BODY_BUFFER`, `TUNNEL_RELAY_BUFFER`,
  `RELOAD_MIN_INTERVAL`، و در موج ۶ `LOGSHIP_*`) — نیازی به ست‌کردن نیست مگر بخواهید تنظیم دقیق کنید؛
  فهرست در `docs/EDGE.md`.
- **موج ۶:** ریدایرکت‌ها، قوانین تبدیل، بسته‌های WAF، مدیریت ربات، mTLS مبدأ، Origin Shield، کش پیشرفته،
  آمار زنده و ارسال لاگ. فرمت لاگ nginx چند فیلد تازه گرفته، پس هر نود بعد از ارتقا **یک بار** nginx را
  reload می‌کند. جزئیات و تنظیمات اختیاری (مثل HTTP/3 که با `--http3` روشن می‌شود و UDP/443 باز لازم
  دارد): `docs/NODES.md` §۱۱.

اگر به هر دلیل `bootstrap.sh` در دسترس نبود، روی خودِ نود از نسخه‌ی کد کنار نود اجرا کنید:

```bash
cd /opt/pcdn && git pull
cd /opt/pcdn/edge && sudo ./install.sh --upgrade
```

> اگر بعد از ارتقا در داشبورد نود خطای `nginx -t failed` دیدید (مثلاً `{{...}}` جایگزین‌نشده)، یعنی عامل قدیمی
> هنوز در حال اجراست: `sudo systemctl restart pcdn-agent && sleep 3 && sudo nginx -t`. نسخه‌ی فعلی
> `install.sh` این ری‌استارت را خودش انجام می‌دهد.

بعد از ارتقا، در پنل مدیریت WHMCS → بخش نودها، سلامت نود و «آدرس‌ها» را ببینید. نودهای عقب‌افتاده نشانِ
«به‌روزرسانی موجود است» می‌گیرند.

> اگر نودی را تازه اضافه می‌کنید (نه ارتقا)، همان یک‌خطی که پنل می‌دهد (توکن در `PCDN_EDGE_TOKEN`) را با `--controller` و در صورت نیاز
> `--region` و `--role` اجرا کنید (راهنمای کامل: `docs/NODES.md`).

## ۳) WHMCS

### ۳-۱) جایگزینی فایل‌های ماژول

دو پوشه‌ی ماژول را با نسخه‌ی جدید جایگزین کنید (فایل‌های قبلی را دور نریزید؛ کنار بگذارید):

- `whmcs/modules/servers/pasargadcdn/`  → به `.../modules/servers/pasargadcdn/` روی سرور WHMCS
- `whmcs/modules/addons/pasargadcdn_admin/`  → به `.../modules/addons/pasargadcdn_admin/`

ساده‌ترین راه: فایل zip ماژول‌ها (`pasargadcdn-whmcs-modules.zip`) را در **ریشه‌ی نصب WHMCS** (همان پوشه‌ای
که `configuration.php` در آن است) باز کنید تا هر دو پوشه سر جای خود بنشینند. چون فایل‌های تازه‌ای در
موج ۶ اضافه شده‌اند (`assets/rules.js`، `assets/platform.js`، `lib/TeamAccess.php`)، کل پوشه را جایگزین
کنید، نه فقط فایل‌های تغییرکرده. نسخه‌ی فایل‌های JS/CSS در آدرسشان می‌آید، پس کش مرورگر مشکلی ایجاد
نمی‌کند.

جدول‌های داخلی ماژول (`mod_pasargadcdn_*` از جمله جدول‌های جدیدِ نماینده و آدرس و مصرف) هنگام نخستین
بارگذاری افزونه **خودکار** ساخته/به‌روزرسانی می‌شوند. اگر افزونه فعال است، یک‌بار صفحه‌ی آن را در پنل
مدیریت باز کنید.

> در CI نسخه‌ی واقعی WHMCS وجود ندارد؛ فهرست فرض‌ها و APIهای WHMCS که باید روی نصبِ staging بررسی شوند
> در `docs/WHMCS.md` آمده است. توصیه می‌شود اول روی یک نصبِ آزمایشی اعمال کنید.

### ۳-۲) یکی‌کردن محصول (CDN + تونل)

در پنل مدیریت: **Addons → مدیریت CDN پاسارگاد → راه‌اندازی خودکار محصولات** را در حالت به‌روزرسانی
اجرا کنید. این کار تونل را روی هر ۴ پلن CDN روشن می‌کند و پلن‌های تونلِ جداگانه را دیگر نمی‌سازد
(قیمت‌ها تغییر نمی‌کند؛ ترافیک تونل از همان سهمیه/کیف‌پول همان سرویس حساب می‌شود).

### ۳-۳) فعال‌سازی تونل روی سرویس‌های موجود

بعد از مرحله‌ی قبل، عملیات **«فعال‌سازی تونل روی سرویس‌های فعلی»** را اجرا کنید تا سرویس‌هایی که از قبل
ساخته شده‌اند هم تونل بگیرند (گزینه‌ی configۀ آپشن‌شان روشن می‌شود و پلن مؤثر دوباره به کنترلر فرستاده
می‌شود). این عملیات idempotent است و به صورت‌حساب دست نمی‌زند؛ می‌توانید بی‌خطر دوباره اجرایش کنید.

### ۳-۴) بررسی

- یک سرویس CDN را باز کنید؛ باید بخش «تونل» و آموزش راه‌اندازی (کلاینت/سرور + QR) دیده شود.
- صفحه‌های موج ۶ در پنل مشتری: «قوانین» (ریدایرکت‌ها و قوانین تبدیل)، «مدیریت ربات‌ها»، کارت‌های
  تازه‌ی WAF/SSL/کش، حالت «زنده» در آمار، «ارسال لاگ»، «وب‌هوک‌ها» و «گزارش SLA». این صفحه‌ها فقط وقتی
  دیده می‌شوند که کنترلر به‌روز شده باشد.
- صفحه‌های موج ۷ در گروه «تونل»: «کیفیت تونل»، «مصرف تونل»، «بررسی کانفیگ سرور» و «تست سرعت»؛
  و در «پیکربندی آماده» راهنمای هفت اپ. در پنل مدیریت «راه‌اندازی خودکار محصولات» را یک بار دیگر اجرا
  کنید تا قالب‌های ایمیل قطعی تونل و افزونه‌های «بسته‌ی ترافیک افزوده» ساخته شوند؛ سپس قیمت افزونه‌ها را
  تعیین و «Show on Order» را روشن کنید.
- **دسترسی تیمی:** کاربری از حساب مشتری که مالک نیست و اجازه‌ی «مدیریت محصولات» (`manageproducts`) ندارد،
  پنل را فقط‌خواندنی می‌بیند. این را با یک کاربر آزمایشی روی WHMCS خودتان امتحان کنید (فهرست APIهای WHMCS
  که باید بررسی شود در `docs/WHMCS.md` بخش «دسترسی تیمی» است).
- در پنل مدیریت: نودها، آدرس‌ها، لاگ‌ها، نمایندگان، گزارش مصرف، و صفحه‌های جدیدِ موج ۵ —
  **«حسابرسی»** و **«سلامت سامانه»** — را یک‌بار مرور کنید (با جایگزینی فایل‌های افزونه خودکار اضافه می‌شوند؛ قدم اضافه‌ای ندارند).

## ۴) بعد از به‌روزرسانی — چک‌لیست

- [ ] `manage current` نسخه‌ی دیتابیس = آخرین نسخه (`0019`).
- [ ] `https://<دامنه-کنترلر>/healthz` سالم و `‎/metrics` پاسخ می‌دهد.
- [ ] همه‌ی نودها در پنل سبز و بدون نشانِ «به‌روزرسانی موجود».
- [ ] یک سرویس تست: DNS، SSL، و یک مسیر تونل آزمایشی کار می‌کند.
- [ ] «راه‌اندازی خودکار محصولات» و «فعال‌سازی تونل روی سرویس‌های فعلی» اجرا شده‌اند.
- [ ] صفحه‌های «حسابرسی» و «سلامت سامانه» در پنل مدیریت باز می‌شوند.
- [ ] در پنل مدیریت → نودها، زیر هر نود نشان «آمار زنده» دیده می‌شود (یعنی عامل موج ۶ روی آن است).
- [ ] یک سایت تست: یک ریدایرکت، حالت «زنده»‌ی آمار، و (اختیاری) یک وب‌هوک با «ارسال آزمایشی» کار می‌کند.
- [ ] (اختیاری) اگر نودی را برای Origin Shield انتخاب کرده‌اید، کلید Shield آن روشن است.

## ۵) بازگشت (در صورت نیاز)

- کنترلر: به نسخه‌ی کد قبلی برگردید و `docker compose up -d --build`؛ در صورت نیاز به بازگرداندنِ
  دیتابیس از پشتیبان مرحله‌ی ۰ استفاده کنید (برگرداندنِ مهاجرت فقط با پشتیبان و احتیاط —
  `docs/OPERATIONS.md`).
- نودها: فایل‌های نود نسخه‌دار نیستند؛ برای برگشت، نسخه‌ی قبلی بسته را دوباره نصب کنید.
- WHMCS: پوشه‌های ماژولِ کنارگذاشته را بازگردانید. جدول‌های `mod_pasargadcdn_*` بی‌خطر باقی می‌مانند.

## ۶) موج ۸ — کارهای اضافه (فقط اگر این امکانات را می‌خواهید)

همه‌ی موارد زیر اختیاری‌اند و بدون آن‌ها سامانه مثل قبل کار می‌کند.

**سرور پنل (`/opt/pcdn/.env`):**
- پروکسی TCP/UDP: `L4_PORT_RANGE=20000-29999` (پیش‌فرض)، `L4_RESERVED_PORTS` (اختیاری).
- رکوردهای وزن‌دار: `RECORD_PROBE_ENABLED=true`، `RECORD_PROBE_TIMEOUT=5`.
- Edge Functions: `FUNCTIONS_MAX_SITE_KB=8192` (پیش‌فرض).
- فضای ذخیره‌سازی: `STORAGE_ENDPOINT`, `STORAGE_ADMIN_ACCESS_KEY`, `STORAGE_ADMIN_SECRET_KEY` و بقیه طبق
  `docs/STORAGE.md` — اول سرور ذخیره‌سازی را با `deploy/storage` راه بیندازید.
- DNS ثانویه: در `dns/pdns.conf` گزینه‌ی `secondary=yes` اضافه شده؛ بعد از `git pull` کانتینر PowerDNS را
  دوباره بالا بیاورید: `docker compose up -d --force-recreate pdns` (نام سرویس را با compose خودتان تطبیق دهید).

**هر نود:**
- ارتقای معمول (`--upgrade`) ماژول stream و include آن را در `nginx.conf` اضافه می‌کند؛ هر نود یک بار reload می‌شود.
- **فایروال:** بازه‌ی `L4_PORT_RANGE` را برای **TCP و UDP** باز کنید (فقط اگر پروکسی TCP/UDP می‌فروشید).
- اختیاری: `--harden-net` (محافظ SYN flood و …؛ اگر SYN proxy را روشن کنید اتصال‌های قدیمیِ ثبت‌نشده یک
  بار قطع می‌شوند)، `--avif` (تبدیل AVIF)، `--functions` (Edge Functions؛ بعد از نصب با
  `systemctl status pcdn-fn` و `cat /run/pcdn-fn/status.json` بررسی کنید که `ok: true` است).
  مثال: `cd /opt/pcdn/edge && sudo ./install.sh --upgrade --functions --harden-net`
- جزئیات: `docs/NODES.md` §۱۲.

**WHMCS:**
- فایل zip جدید را مثل قبل در ریشه‌ی WHMCS باز کنید (کل پوشه‌ها را جایگزین کنید).
- پنل مشتری حالا فارسی/انگلیسی است (دکمه‌ی EN/FA؛ زبان پیش‌فرض از زبان کاربر در WHMCS).
- اگر Edge Functions می‌فروشید، وب‌سرورِ جلوی WHMCS باید بدنه‌ی درخواست تا **۹ مگابایت** را بپذیرد
  (مثلاً `client_max_body_size 10m;` در nginx یا `post_max_size`/`upload_max_filesize` ≥ 10M در PHP).
- گزینه‌های پیکربندی تازه (اختیاری، در محصول): `L4 Proxy`، `L4 Apps`، `Edge Functions`، `Max Functions`،
  `Storage GB`؛ و در تنظیمات افزونه «قیمت هر گیگابایت-ماه ذخیره‌سازی».

**ابزارها:**
- تست بار برای تعیین ظرفیت نودها: `docs/LOADTEST.md`.
- خط فرمان `pcdn` و انتشار امضاشده: `docs/CLI.md`؛ Terraform: `docs/TERRAFORM.md`.

## ۷) موج ۹ — کارهای لازم بعد از این به‌روزرسانی

این بخش برخلاف موج ۸ **اختیاری نیست**؛ چند مورد امنیتی رفتار پیش‌فرض را عوض کرده است.

**سرور پنل:**
- مهاجرت `0019` خودکار اجرا می‌شود. برگشت به پایین‌تر از `0002` وقتی رمزنگاری اسرار فعال است عمداً
  متوقف می‌شود (فقط با پشتیبان برگردید).
- صفحه‌های `‎/docs` و `‎/openapi.json` کنترلر دیگر عمومی نیستند؛ مستندات API مشتری در
  `‎/capi/v1/openapi.json` است.
- API PowerDNS فقط از شبکه‌های خصوصی پذیرفته می‌شود (`PDNS_API_ALLOW_FROM` در `.env`؛ پیش‌فرض
  127.0.0.1 و بازه‌های خصوصی). اگر کنترلر با IP عمومی به PowerDNS وصل می‌شود، آن IP را اضافه کنید.
- **سرور ns2:** در `deploy/ns2-compose.yml` متغیر `PDNS_API_ALLOW_FROM` حالا **اجباری** است — IP کنترلر
  با `/32`؛ بدون آن کانتینر بالا نمی‌آید.
- کلیدهای API مشتری که قبلاً ساخته شده‌اند دسترسی `functions` را ندارند؛ مشتری اگر لازم دارد کلید جدید
  با این دسترسی بسازد.
- ریدایرکت/بازنویسی با regex خطرناک (تکرار تودرتو) یا حروف غیر ASCII دیگر پذیرفته نمی‌شود؛ ذخیره‌ی
  قبلی‌ها با خطای روشن رد می‌شود تا مشتری اصلاحش کند.

**هر نود:**
- `cd /opt/pcdn/edge && sudo ./install.sh --upgrade` — عامل حالا یک بسته است
  (`/usr/local/lib/pcdn/pcdn_agent/`)؛ ارتقا نسخه‌ی تک‌فایلی قبلی را خودکار جایگزین می‌کند.
- **محافظ آدرس مبدأ** (`pcdn_origin_guard`) پیش‌فرض روشن است: نود به آدرس‌های خصوصی/داخلی وصل نمی‌شود.
  اگر مشتری‌ای مبدأ با IP خصوصی دارد (مثلاً شبکه‌ی داخلی دیتاسنتر)، بازه را در
  `/etc/pcdn/agent.conf` بگذارید (`ORIGIN_PRIVATE_ALLOW=10.20.0.0/16,10.30.0.0/16`) و دوباره
  `./install.sh --upgrade` بزنید. برای خاموش کردن کامل: `--upgrade --no-origin-guard` (توصیه نمی‌شود).
- نصب نود جدید: توکن را در متغیر محیطی بدهید (در تاریخچه‌ی shell و `ps` دیده نمی‌شود):
  `curl -fsSL <controller>/edge/install.sh | sudo PCDN_EDGE_TOKEN=<token> bash -s -- --controller <url>`

**WHMCS:**
- zip جدید را باز کنید (کل پوشه‌ها را جایگزین کنید).
- **یک بار** «سایت‌ها ← گزارش همگام‌سازی ← همگام‌سازی مالکیت دامنه‌ها» را بزنید تا سایت‌های قدیمی مالک
  بگیرند (کران هم به‌تدریج انجامش می‌دهد).
- اختیاری: آزمایش رایگان، گزارش‌های ایمیلی زمان‌بندی‌شده، امکانات نماینده — `docs/WHMCS.md`.
- حالت یادگیری WAF در صفحه‌ی WAF پنل مشتری خودکار ظاهر می‌شود (بعد از ارتقای کنترلر و نودها).

**ابزارهای عملیاتی (اختیاری):** محیط staging (`docs/STAGING.md`)، پایش Prometheus/Grafana
(`docs/MONITORING.md`)، صفحه‌ی وضعیت جدا (`deploy/status`)، تمرین ماهانه‌ی بازیابی
(`docs/DISASTER_RECOVERY.md` §۸–۹)، سایت مستندات (`mkdocs serve`).
